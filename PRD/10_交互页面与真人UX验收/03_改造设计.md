# 剧情化狼人杀改造 — 完整设计（待审核，未实现）

> 目标：把产品从「狼人杀事件日志查看器」改为「一个人随时可玩、六名 AI 有鲜明人格、会彼此回应、能记住前言后语的剧情化狼人杀」。
> 本轮范围：对局体验 + AI 人格 + 圆桌 UI。**不修改角色规则、胜负规则、欺骗阈值、平衡参数。**
> 旧 UX 验收版本作废；完成后重新冻结版本、重新招募 5 名真人测试者。

## 0. 已确认决策（4 项）

1. **模式按房间选择**：首页「离线演示 / 真实 LLM」，经 `create_room.ai_mode` 传入。客户端**只能选模式**，不能提交 API Key / Provider 地址 / 任意模型名；真实模型配置由服务端启动时读取。服务端返回并展示 `effective_ai_mode`；选真实但未配置 → 直接报错，禁止静默降级。
2. **Mock = 确定性规则生成器**：接受「语言能力有限但人格可辨」；必须按人格 + 真实事件 + 历史发言 + 票型组合内容（非每人格几句固定台词）；同 seed 可复现、零联网、零成本。
3. **真实 LLM 每次决策只调用一次**：一次结构化输出同时完成「行为规划 + 最终台词」；保留 `speech_act/target/claim/evidence/intended_vote/stance_changed/change_reason/statement`；先校验结构与事实，再走现有一次重试 + 兜底。
4. **人格盲测门槛**：≥4/5 名测试者，每人正确匹配 ≥4/6 人格；盲测材料给**每个人格跨 2–3 回合的匿名发言 + 行为片段**（非单句、非关键词标签）。

## 1. 数据结构

### 1.1 AgentMemory（`ai/memory.py`，新增，每席位一份）
```python
@dataclass
class AgentMemory:
    statements: list[str] = field(default_factory=list)     # 最近公开发言，cap 8
    votes: list[dict] = field(default_factory=list)          # {"day": int, "target": int}
    suspicion_log: list[dict] = field(default_factory=list)  # {"day": int, "key_player": int|None, "delta": float}
    questioned_by: list[int] = field(default_factory=list)   # 最近质疑我的人，去重，cap 8
    allies: list[int] = field(default_factory=list)          # 我支持/辩护过的人，去重
    conflicts: list[int] = field(default_factory=list)       # 我攻击/怀疑过的人，去重
    promises: list[str] = field(default_factory=list)        # 我公开承诺的立场，cap 4
    recent_phrases: list[str] = field(default_factory=list)  # 反重复，cap 16

    def summarize(self) -> dict: ...   # 注入 prompt / hint
    def update(self, action, view) -> None: ...  # 每次决策后追加
```
- 存于 **LLMBot（服务端、每席位）** → 刷新/断线/重连自动不丢（记忆不在浏览器）。

### 1.2 DialogueContext（`ai/dialogue.py`，新增，Mock 生成器输入）
```python
@dataclass(frozen=True)
class SeatInfo: id: int; name: str; is_human: bool
@dataclass(frozen=True)
class StatementRecord: actor: int; day: int; text: str
@dataclass(frozen=True)
class VoteRecord: day: int; actor: int; target: int; round: int

@dataclass
class DialogueContext:
    persona_id: str
    day: int; phase: str; me: int; role: str; pack: list[int]
    living: list[SeatInfo]
    recent_statements: list[StatementRecord]   # 最近 10 条公开发言
    votes: list[VoteRecord]                    # 全部票型
    top_suspicion: int | None                  # 我当前私下最怀疑对象
    my_last_statement: str | None
    questioned_by: list[int]
    memory_summary: dict                       # AgentMemory.summarize()
```

### 1.3 结构化决策字段（发言类，扩展 LLM/Mock 输出）
```python
# 发言类决策新增（与 suspicion/deception 并存）：
speech_act: "inform|question|reply|analyze|defend|lobby|mediate|deceive"
target: int | None          # 主要回应对象

evidence: list[int] | None  # 可见事件编号（可空）
intended_vote: int | None   # 当前投票倾向

```

### 1.4 DecisionRecord 扩展（`ai/trace.py`，向后兼容）
新增字段（默认值，旧回放不受影响）：`speech_act, target, claim, evidence, intended_vote, stance_changed, change_reason`。

## 2. 协议变更

### 2.1 `/health`（REST）
```json
{"status":"ok", "real_llm_available": true, "model": "deepseek-v4-flash"}
```
- `real_llm_available`：服务端启动时是否读到完整真实模型配置（Key + model + base_url）。
- `model`：配置的模型名（**无 Key、无 Provider 地址**）；未配置为 null。

### 2.2 `create_room`（客户端 → 服务端）
```json
{"type":"create_room", "data":{"ai_mode":"offline"}}   // "offline" | "real"，缺省 offline
```
- 客户端只传 `ai_mode`，**不传 Key / Provider / model**。
- 校验：`ai_mode` 非 offline/real → `server_error`；`real` 且 `real_llm_available=false` → 新错误码 `provider_unavailable`（消息列出缺失项名，不含值）。
- 大厅在创建前**明确展示**：当前默认选择为「离线演示 AI」；离线模式语言能力有限；用户可主动切换「真实 LLM」。

### 2.3 `room_created`（服务端 → 客户端）
```json
{"type":"room_created", "data":{"room_id":"…","join_secret":"…","effective_ai_mode":"offline"}}
```

### 2.4 新错误码
`provider_unavailable`：真实 LLM 未配置，禁止降级。

### 2.5 `game_started.seats`
每个座位增加 `is_human`：
```json
{"id":0,"name":"你","alive":true,"is_human":true}
```

### 2.6 大厅模式徽标
- 首页据 `/health` 展示「离线演示 AI / 真实 LLM（已配置或不可用）」。
- 对局顶部常驻 `effective_ai_mode` 徽标：离线演示显示「离线演示 AI · 语言能力有限」；真实显示「真实 LLM · {model}」。

## 3. Mock 生成规则（`ai/dialogue.py`）

### 3.1 输入
`build_prompt` 构造 `DialogueContext`（从 `PlayerView` + `AgentMemory` + request 提取），随 `Prompt.hint` 传给 `MockProvider`。

### 3.2 流程
```
判定局势 → 按人格权重选行为 → 按人格语言特征填充真实引用 → 反编造/反重复检查
```

**局势判定**：
- `low_info`：本天尚无发言；
- `questioned`：`me in questioned_by`；
- `has_votes`：存在票型；
- `wolf_mislead`：`role=="werewolf"` 时强制走误导（攻击非狼队友）。

**行为选择（非“按权重随机抽”）**：
1. 先按局势筛出**合理**行为（无人质疑我 → 排除 `defend`；无分歧 → 排除 `mediate`；非狼人 → 排除欺骗）。
2. 用**得分**排序选行为：
   `得分 = 局势相关性 + 人格权重 + 本轮战略需要 − 最近行为重复惩罚`
3. 狼人欺骗**不进入普通权重表**：仅狼人在存在战略机会时触发，`deception_tendency` 作修正。

**speech_act 权重表（首版先验，非真实概率）**：

| 人格 | question | analyze | accuse | defend | support | lobby | mediate |
|---|---:|---:|---:|---:|---:|---:|---:|
| 质疑者 | .35 | .25 | .15 | .10 | .03 | .07 | .05 |
| 老好人 | .10 | .15 | .05 | .10 | .35 | .05 | .20 |
| 分析家 | .10 | .45 | .12 | .08 | .08 | .10 | .07 |
| 激进派 | .08 | .12 | .20 | .10 | .03 | .42 | .05 |
| 和事佬 | .12 | .18 | .05 | .08 | .15 | .07 | .35 |
| 话痨 | .18 | .15 | .16 | .12 | .10 | .20 | .09 |

**六维度影响映射（保留）**：
- `trust_baseline` → 目标判断；`evidence_sensitivity` → 证据选择；`risk_preference` → 行动风险；`lobby_strength` → 拉票强度；`vote_resistance` → 改口概率；`deception_tendency` → 狼人欺骗修正。

**语言特征（每人格 voice 片段，非整句模板）**：
- 质疑者：开头「我有个疑问 / 这我想不通 / 先不急着定狼」；多用问句；要求证据。
- 老好人：开头「我觉得 / 先别急」；先给合理解释，再弱表态。
- 分析家：开头「先看事实 / 我分几点说」；用「第一、第二」；克制。
- 激进派：开头「没别的 / 很明显」；「Px 就是狼，跟我投」；强拉票。
- 和事佬：开头「大家听我说 / 争议在于」；总结双方再「建议统一投 Px」。
- 话痨：开头「哎呀这个局面 / 我先啰嗦两句」；长句、多从句、一次回应多人。

**组合规则**：
1. 选 `target`（真实对象）：被质疑→质疑者；有票型矛盾→矛盾来源；狼人误导→非狼队友中威胁最高者；否则 `top_suspicion`。
2. 生成 `claim`：有事实→引用事实；无事实→「目前信息不足，先听一轮」。
3. 用 voice 开头/连接词/结尾 + 真实 `P{target}` 编号组装成句。
4. 长度按人格调制（话痨 +2~3 从句，分析家分点，老好人/激进派更短）。

**反编造/反重复**：
- 只引用 `recent_statements/votes/living` 中的真实事实，否则「信息不足」。
- 与 `memory.recent_phrases` 完全重复 → 换一个 voice 开头重排一次。

**确定性**：同 game seed + day + 席位 + 发言序 → 同输出。

## 4. 真实 LLM Prompt / 输出契约

### 4.1 Prompt 组成（每次决策一次调用）
- **System**：身份 + 规则 + 该人格 voice 描述 + 输出 JSON schema + 反编造/权限/立场规则。
- **User**：day/phase、存活玩家、最近公开发言（对话记忆）、票型、我的记忆摘要、我的怀疑分数、我的角色/狼队友（仅限我有权知道）、本轮任务。

### 4.2 输出 JSON（发言类）
```json
{
  "reasoning": "...",
  "speech_act": "question|reply|analyze|defend|lobby|mediate|deceive|inform",
  "target": 4,
  "claim": "P4 昨天的票和发言矛盾",
  "evidence": [12, 15],
  "intended_vote": 4,
  "stance_changed": true,
  "change_reason": "因为 P4 昨天投了已被证实的狼",
  "statement": "我有个疑问，P4 你昨天说信 P2，今天却投了 P2，能解释吗",
  "private_suspicion": {}, "public_suspicion": {}, "strategic_threat": {},
  "deception": {}, "confidence": 0.8
}
```

### 4.3 校验顺序（`llm_bot.py`，一次重试 + 兜底前）
1. **结构**：JSON 解析 + 字段类型齐备。
2. **事实**：`evidence` 必须指向可见事件；`claim` 有依据，或 `statement` 明确「信息不足」；不得引用不存在的历史。
3. **权限**：不得使用角色无权知道的信息。
4. **立场**：`stance_changed=true` 必须有 `change_reason`；无变化却改口 → 重试。
5. **重复**：`statement` 与 `memory.recent_phrases` 雷同 → 重试。
6. 再走现有 suspicion/deception 校验 → 一次重试 → 合法兜底（不中断对局）。

## 5. 圆桌 UI 信息架构

```
顶部：第X天 | 阶段 | 当前任务 | 引导/快速切换 | AI 模式徽标（离线演示AI/真实LLM）
中央：7 人圆桌（每座：P号、名字、性格名、存活/死亡、发言中高亮、已投票✓、允许知道的身份）
底部：真人当前操作区 + 倒计时（轮到我时高亮 + 滚动可见）
右侧：Copilot / 我的私密信息 / 笔记
抽屉：完整对局日志（默认折叠，仅查证/复盘）
```

- 发言：一次高亮一位 AI，座位旁气泡；系统播报（死亡/天亮/阶段）与玩家发言视觉分离。
- 数据来源：`game_started.seats`（含 is_human）；发言/投票由事件流驱动。
- **身份三通道分离（防断线补发/前端合并泄漏）**：
  - `公开身份`：对局中除真人自己外一律显示 `?`，死亡不公开，终局一次性揭晓（`game_over.seats`）。
  - `本人私密已知信息`（仅真人可见，独立状态，不写入公开字段）：自己的角色；狼人→标记狼队友；预言家→标记已查验阵营结果。
  - `终局身份`：`game_over.seats` 全量揭晓，走独立渲染路径。
- 首页流程：`第一次玩/我会玩` → `离线演示AI/真实LLM`（据 `/health` 可用性）→ `认识六名AI` → 建房入座 → 身份揭晓 → 圆桌。
