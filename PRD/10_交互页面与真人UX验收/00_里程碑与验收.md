# 交互页面 + 真人 UX 验收 — 里程碑

> 状态：已立项，待评审关键决策。
> 前置：规则结论已定（#5/#6 定稿，#1–#4 维持现状）；单真人 WebSocket 服务端已完成；AI 技术验收已通过。
> 一句话目标：回答「**普通人玩起来是否看得懂、会不会卡住、Copilot 是否有用**」。

## 1. 为什么现在做这个

- 规则、WebSocket、AI 技术验收都已完成；唯一未知的是**真人体验**。
- 不能靠调规则/人格/阈值去猜体验问题——那只会把问题从一处移到另一处。
- 服务端已就绪：`decision_request` 已携带 `prompt`、`copilot`、`legal_targets`、`suggestions`、`deadline_ms`；本里程碑**主要是前端呈现 + UX 评测，不改后端规则**。

## 2. 范围

### 做
- 一个**最小可用的 Web 交互页面**，复用现有 WebSocket 服务端（`create_ws_app`）。
- 完整流程：建房 → 入座 → 开局 → 看身份/夜晚 → 讨论/投票 → 终局 → 回放。
- Copilot 呈现：嫌疑概率 + 投票建议（已有 `decision_request.copilot` 下发）。
- 真人 UX 验收：小样本真人试玩 + 观察指标 + 结论。

### 不做（本里程碑）
- 不调规则、人格、欺骗阈值（维持现状；发现平衡/体验问题只**记录**，不改）。
- 不做多真人混房、语音、账号体系、SQLite 战绩、Admin 后台。
- 不做正式部署/运维（先本地可跑，必要时再谈云端）。

## 3. 交付物

1. 静态 Web 客户端（HTML/CSS/JS，由 FastAPI 直接服务，无构建链）。
2. UX 验收方案 + 观察记录模板（任务清单、观察点、问卷）。
3. 验收结论：三项打分（看得懂 / 不卡住 / Copilot 有用）+ 改进清单。

## 4. UX 验收成功标准（草案，待定稿）

| 维度 | 要回答的问题 | 建议门槛 |
|---|---|---|
| 看得懂 | 我能知道「我是谁、现在什么阶段、我该做什么」吗？ | ≥4/5 测试者无需外部帮助 |
| 不卡住 | 从入座到终局，我会不会因界面/流程而无法继续？ | 0 人中途中止；卡点都能归因到界面而非规则 |
| Copilot 有用 | 嫌疑提示 + 投票建议对我做决定有帮助吗？ | ≥4/5 认为「有帮助」（含「有帮助但不够」） |

## 5. 关键待决（需要你拍板）

1. **前端形态**：纯静态 HTML+JS（推荐，最小、零构建）还是框架（React/Vue）？
2. **运行方式**：本地 `uvicorn` + 浏览器打开，还是先部署到云端（妙搭 / veFaaS）？
3. **UX 验收细节**：测试者人数、任务清单、观察方式（问卷 / 录屏 / 出声思考）、语言（当前 AI 提示为中文）。
4. **Copilot 呈现形态**：沿用文本，还是加概率条 / 嫌疑排序可视化。

## 6. 明确风险与边界

- 本里程碑**不解决狼方胜率偏强**；若试玩发现「狼太强导致体验差」，只记录为平衡信号，不在此改规则。
- 脚本/AI 对局不能替代真人体验结论；结论必须来自真实玩家试玩。
